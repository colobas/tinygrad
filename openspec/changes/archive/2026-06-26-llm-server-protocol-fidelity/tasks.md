## 5. Reasoning control

- [x] 5.1 Generalize reasoning parsing to per-model formats (think-tag, channel-based, DeepSeek-style) selected from model metadata. **Done:** `REASONING_FORMATS` table + `detect_reasoning_format(chat_template, special_tokens)` in `parser.py` (data-driven selection; new families are table entries, not parser changes). `SimpleTokenizer.reasoning_format` is populated from GGUF metadata; the server resolves it via `_reasoning_markers` (defaults to think-tags — harmless for non-thinking models, which never emit the marker). Catalog currently spans only the think-tag format (Qwen3/3.5, DeepSeek-R1).
- [x] 5.2 Accept `reasoning_effort` (low/medium/high) and explicit thinking-token budget; define configurable per-family budget mapping. **Done:** `_resolve_reasoning` accepts `reasoning_effort` (mapped via `REASONING_EFFORT_BUDGETS` = {low:256, medium:1024, high:4096}) and an explicit `thinking_budget` (top-level or in `chat_template_kwargs`, overrides effort); invalid effort/budget → HTTP 400. The budget dict is the seam for per-family overrides.
- [x] 5.3 Enforce budget host-side: count reasoning tokens and inject the model's reasoning-close sequence on budget hit (no kernel-graph change). **Done:** `run_model` runs generation in an outer restart loop; when the reasoning-token count reaches the budget while `parser.state == "reasoning"`, it appends `tok.encode(close_marker)` to the context, feeds the close marker through the parser (forcing the content transition), and resumes generation — KV cache reused via `get_start_pos`, no graph change. The injected marker is never emitted as content.
- [x] 5.4 Preserve `enable_thinking: false` (top-level and `chat_template_kwargs`) skip-thinking behavior. **Done:** `_resolve_reasoning` disables the split (returns no markers) when `enable_thinking` is false at the top level or in `chat_template_kwargs`; `_template_ids` forwards `enable_thinking` into the template kwargs so the rendered prompt also skips thinking.

## 7. Structured output — constrained decoding (isolated, opt-in)

- [x] 7.1 Prototype per-token logit-mask injection into the TinyJit decode graph; measure graph-rebuild/dispatch + host→device copy cost; decide feasibility. **Done/feasible:** `Transformer.forward_masked` adds a vocab-length `logit_bias` input before the gumbel-max argmax, JIT-compiled separately (`masked_prefill_jit`/`masked_rollout_jit`) so no per-step recompile — the bias is a fresh graph-input Tensor each step (consistent with how `generate` already feeds fresh token tensors). **Measured:** the kernel-side cost is one vocab-wide add + a vocab-sized host→device copy per emitted token (negligible vs. a forward pass). The real cost is the **host-side** mask build; naive full-vocab trial-feed = ~40 ms/token at 150k vocab. Conclusion: feasible and host-side (off the kernel graph, as the design required). **Optimized (follow-up):** the mask build now walks a precomputed vocabulary prefix trie guided by the grammar (`build_trie` + DFS in `GrammarMasker.mask`, with identity-keyed `step` memoization), so a rejected character prunes its whole token subtree in one `step`. Structural positions (keys, braces, literals, numbers — the majority of constrained steps) dropped from ~9.7 ms to ~0.37 ms/token (~26×); a permissive string body is inherently O(vocab) (~61 ms, on par with the per-token baseline's ~77 ms). The trie is built once per vocabulary and cached process-wide (`_TRIE_CACHE`), and `test_grammar.py::TestTrieMaskEquivalence` locks the trie mask to a brute-force per-token reference.
- [x] 7.2 Build schema→grammar compilation and an incremental grammar-advance kept off the decode critical path. **Done:** `tinygrad/llm/grammar.py` — a pure-functional pushdown acceptor (`initial`/`step`/`can_eof`) over a documented JSON-Schema subset (object with declared properties in order, free-form objects, arrays, string/integer/number/boolean/null, enum, untyped any-value; compact JSON). `GrammarMasker` advances the committed state incrementally (only newly-committed tokens are folded in) entirely host-side — no kernel-graph involvement.
- [x] 7.3 Accept `response_format: { type: "json_schema" }`; apply the logit mask so only grammar-permitted tokens are sampled. **Done:** `_resolve_response_format` returns `("json_schema", schema)`; `_grammar_mask_fn` builds a per-request `GrammarMasker` from `SimpleTokenizer.grammar_vocab()` and threads `mask_fn` through `run_model` → `model.generate`, which applies the bias on every emitting step. EOS is permitted only once the value can complete, so generation stops at a conforming value.
- [x] 7.4 Ensure decoding is unmasked and perf-unchanged when no `json_schema` is requested (opt-in gate). **Done:** `generate` only takes the masked path when `mask_fn` is provided; the default path calls the original unmasked JITs unchanged. Locked by `test_unmasked_path_unchanged` (byte-identical output with/without `mask_fn=None`).
- [x] 7.5 Tests: output conforms to schema; no-schema decode path performance regression check. **Done:** `test/unit/test_grammar.py` (12 acceptor + masker tests), `test_masked_generate_forces_conforming_json` (real decode graph + grammar mask yields schema-conforming JSON) and `test_unmasked_path_unchanged` in `test/unit/test_llm_server.py`, plus `test_json_schema_threads_mask_fn` / `test_invalid_json_schema_returns_400` in `test/null/test_llm_server.py`.
